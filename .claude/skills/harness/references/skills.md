# 스킬 작성법

목적: `.claude/skills/*/SKILL.md` 스킬을 공식 규격과 하네스 원칙에 맞게 작성한다.

## 파일 규격

`.claude/skills/<name>/SKILL.md`, frontmatter + 본문. 보조 파일은 같은 디렉토리(`references/`, `scripts/`)에 둔다.

| 필드 | 필수 | 의미 |
|---|---|---|
| `name` | | 스킬 리스팅에 보이는 표시명. 생략 시 디렉토리명. 개인·프로젝트 스킬의 호출 명령명은 디렉토리명으로 고정이라 이 필드로 바꿀 수 없다(플러그인 스킬만 예외) |
| `description` | 권장 | 무엇을 하는지·언제 쓰는지. 모델의 자동 로드 판단 근거. `when_to_use`와 합쳐 1,536자 한도 |
| `disable-model-invocation` | | `true`면 사용자 `/호출`만 가능. 절차형(Task) 스킬에 권장 |
| `user-invocable` | | `false`면 모델만 로드. 배경 지식(Reference) 스킬에 고려 |
| `allowed-tools` | | 호출 턴에 권한 프롬프트 없이 쓸 도구 |
| `argument-hint` / `arguments` | | `/호출` 인수 힌트·이름 인수 (`$name` 치환) |
| `context: fork` | | 분리된 서브에이전트에서 실행. `agent`·`background`와 함께 사용 |
| `paths` | | glob 매칭 파일 작업 중일 때만 자동 로드 |

그 외 필드(`model`, `effort`, `hooks`, `shell` 등)는 필요할 때 공식 문서를 확인한다.

## 작성 규칙

- **description — 로드 판단 기준**: 읽는 주체는 사용자 요청과 매칭하는 모델이다. 핵심 사용 사례를 문장 앞에 쓰고, 사용해야 하는 상황과 대상이 아닌 상황(및 그 경우 어디로 가는지)을 서술한다. 트리거 문구를 과다 나열하지 않는다.
- **본문 500줄 이하**: 본문은 호출 후 세션 내내 컨텍스트에 남는다. 상시 필요한 것만 본문에 두고, 특정 단계에서만 필요한 상세는 `references/*.md`로 분리해 로드 시점을 본문에 명시한다 (progressive disclosure).
- **Reference형과 Task형을 구분한다**: 배경 지식·규칙 모음은 자동 로드형으로, 단계적 절차는 `disable-model-invocation: true`로 사용자 호출형으로 만든다.
- **종료 조건**: 절차형 스킬은 언제 완료로 판단하는지를 본문에 명시한다.
- **실패 시 행동**: 절차 중 전제가 어긋나면(필요한 파일·조건 부재 등) 우회하지 않고 멈추고 사용자에게 묻는다.
- **인수**: `/호출`로 입력을 받는 스킬은 `$ARGUMENTS`(또는 이름 인수)를 본문에서 명시적으로 사용한다. 안 쓰면 입력이 끝에 자동으로 붙는다.
- **`!`cmd`` 인젝션**: 실패하면 스킬 호출 전체가 취소된다. 실패 가능한 명령은 `|| true`를 붙인다.
- **경로**: 스킬 내부 파일은 `${CLAUDE_SKILL_DIR}`, 프로젝트 파일은 `${CLAUDE_PROJECT_DIR}` 기준으로 적는다.
- **피드백 경로**: 구성요소가 잘못 판단·동작한 사례는 `.claude/FEEDBACK.md`에 기록한다.

## 템플릿

```markdown
---
name: <소문자-하이픈>
description: <무엇을 하는지>. <사용해야 하는 요청 상황>. <대상이 아닌 상황과 그 처리처>.
---

# <name>

목적: <한 문장>

## 절차

1. <단계. 특정 단계에서만 필요한 상세는 references/<파일>.md를 그 단계에서 읽도록 지시>

## 경계

- 대상: <목적이 미치는 범위>
- 비대상: <미치지 않는 범위>

## 종료 조건

<이 조건을 만족하면 완료로 판단한다>

## 실패 시

<전제가 어긋나면 멈추고 사용자에게 묻는다>

## 검증

- <목적 달성과 호출 적절성을 확인하는 방법>
```

## 검증

- 목적 달성: 대표 요청 하나로 스킬을 실제 로드해 절차대로 완료되는지 확인한다. 본문에 명령을 적었으면 실제로 실행해 본다.
- 호출 적절성: description만 읽고 로드 여부를 판단할 수 있는지 — 대상 요청과 비대상 요청 각 한 가지를 놓고 판별되는지 확인한다.
- 분량: 본문이 500줄 이하인지, 특정 단계 전용 상세가 본문에 남아 있지 않은지 확인한다.
