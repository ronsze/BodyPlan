# 에이전트 작성법

목적: `.claude/agents/*.md` 서브에이전트를 공식 규격과 하네스 원칙에 맞게 작성한다.

## 파일 규격

`.claude/agents/<name>.md`, frontmatter + 본문(시스템 프롬프트).

| 필드 | 필수 | 의미 |
|---|---|---|
| `name` | ✅ | 고유 식별자. 소문자·하이픈만 |
| `description` | ✅ | 위임 판단 기준. 100단어를 넘기지 않는다 — 등록된 모든 에이전트의 description이 항상 컨텍스트에 실린다 |
| `tools` | | 허용 도구 allowlist (쉼표 구분). 생략 시 **모든 도구 허용** |
| `disallowedTools` | | 제외 도구 denylist |
| `model` | | `sonnet`·`opus`·`haiku`·`fable`·`inherit` 또는 전체 모델 ID(`claude-opus-5` 등). 생략 시 부모 세션 모델 |
| `skills` | | 미리 로드할 스킬 |
| `maxTurns` | | 최대 턴 수 |

그 외 필드(`permissionMode`, `memory`, `isolation`, `hooks`)는 필요할 때 공식 문서를 확인한다.

## 작성 규칙

- **목적 줄**: 본문 첫 줄의 목적은 description과 내용이 겹쳐도 유지한다 — 제1원칙이 우선한다.
- **단일 책임**: 에이전트 하나에 목적 하나. 메인 세션과 자주 왕복해야 하는 작업은 에이전트로 만들지 않는다.
- **description — 위임 판단 기준**: 읽는 주체는 사용자가 아니라 위임 여부를 판단하는 오케스트레이터다. 100단어 이내로 쓰고, 넘치는 상세는 본문으로 옮긴다. "이 에이전트에 위임해야 하는 상황"과 "위임하지 말아야 하는 상황(직접 처리 또는 다른 곳)"을 함께 서술한다.
- **입력 계약**: 에이전트는 대화 이력 없이 시작한다. 호출자가 위임 메시지에 반드시 담아야 하는 입력을 명시한다.
- **출력 계약**: 호출자에게는 최종 보고서 하나만 돌아간다. 보고서의 구조와 필수 포함 항목(예: 판정, 근거, 남은 이슈)을 본문에 정의한다.
- **종료 조건**: 언제 끝났다고 판단하는지를 명시한다.
- **실패 시 행동**: 목적을 달성하지 못하면 우회로를 찾지 않고 실패로 보고하고 멈춘다.
- **tools**: 목적에 필요한 도구만 allowlist로 지정한다. 목적 밖 도구를 주지 않는다.
- **model**: 작업 난이도에 맞춰 지정한다. 단순 대조·수집은 하위 모델로 비용을 줄인다.
- **피드백 경로**: 구성요소가 잘못 판단·동작한 사례는 `.claude/FEEDBACK.md`에 기록한다.

## 템플릿

```markdown
---
name: <소문자-하이픈>
description: <무엇을 맡기는지>. <위임해야 하는 상황>. <위임하지 말아야 하는 상황과 그 경우의 처리처>. 위임 메시지에는 <필수 입력>을 반드시 담는다.
tools: <목적에 필요한 도구만>
model: <난이도에 맞는 모델>
---

목적: <한 문장>

## 절차

1. <단계>

## 출력

<보고서 구조와 필수 항목>

## 종료 조건

<이 조건을 만족하면 종료한다>

## 실패 시

<판정 기준> 달성이 불가능하면 시도한 내용과 함께 실패로 보고하고 멈춘다.

## 검증

- <목적 달성과 위임 적절성을 확인하는 방법>
```

## 검증

- 목적 달성: 대표 작업 하나를 실제로 위임해 산출물이 출력 계약과 일치하는지, 종료 조건에서 멈추는지 확인한다.
- 호출 적절성: description만 읽고 위임 여부를 판단할 수 있는지 — 대상 요청과 비대상 요청 각 한 가지를 놓고 판별되는지 확인한다.
- tools 검증: 본문 절차가 요구하는 도구가 allowlist에 모두 있는지, 목적 밖 도구가 없는지 대조한다.
