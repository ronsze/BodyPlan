# rules 작성법

목적: `.claude/rules/*.md` 규칙 파일을 공식 규격과 하네스 원칙에 맞게 작성한다.

## 파일 규격

`.claude/rules/` 아래 `.md` 파일. 하위 디렉토리로 그룹화 가능하며 재귀적으로 발견된다.

frontmatter 필드는 `paths` 하나다:

- `paths` 없음 → 세션 시작 시 무조건 로드 (CLAUDE.md와 동일).
- `paths` 있음 → 매칭 파일을 **읽을 때만** 로드.

glob 문법: `**/*.kt`, `feature/**/*`, brace expansion `src/*.{ts,tsx}`, 여러 패턴은 YAML 배열.

## 작성 규칙

- **파일 하나에 토픽 하나**: 첫 줄에 목적을 서술한다.
- **`paths`를 반드시 지정한다**: `paths` 없는 rules는 상시 로드되어 CLAUDE.md와 구별이 없다 — 그 내용은 CLAUDE.md로 보낸다. 경계는 `paths`가 강제하므로 적용 대상 파일만 매칭되게 좁게 쓴다.
- **내용은 규칙만**: 해당 경로의 파일을 다룰 때 적용할 규칙을 적는다. 절차(멀티스텝)는 스킬로, 전역 지침은 CLAUDE.md로 보낸다.

## 템플릿

```markdown
---
paths:
  - "<적용 대상 glob>"
---

# <토픽>

목적: <한 문장>

- <규칙>
- <규칙. 판단이 갈리는 지점에만 판정 기준 한 줄>
```

## 검증

- 로드 검증: 매칭되는 파일을 Read해 규칙이 컨텍스트에 로드되는지, 비매칭 파일에서는 로드되지 않는지 확인한다.
- 패턴 검증: `paths`의 glob이 의도한 파일 집합과 일치하는지 실제 파일 목록으로 대조한다 (예: `git ls-files '<glob>'`).
- 내용 검증: 규칙이 적용된 결과물(코드)이 규칙과 일치하는지 대표 파일 하나로 확인한다.
