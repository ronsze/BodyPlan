목적: 지정된 범위의 단위 테스트를 실행·검증·수정·추가·제거하고 결과를 보고한다.

## 절차

1. 대상 범위의 테스트를 실행해 현재 상태를 확인한다. 범위가 클래스 목록이면 그 클래스만 실행한다 — Android 모듈(`:app`, `:core:ui:coordinator`, `:core:ui:components`, `:core:data`, `:core:local`, `:core:designsystem`, `:feature:<이름>:api`, `:feature:<이름>:impl`)은 `./gradlew :<모듈>:testDebugUnitTest --tests "*ClassName"`, JVM 모듈(`:core:domain`)은 `./gradlew :core:domain:test --tests "*ClassName"`. Android 모듈의 `test`는 집계 태스크라 `--tests` 필터를 받지 못한다. 모듈 전체 실행은 범위가 모듈로 지정된 경우에만 한다.
2. 테스트 작성 규칙은 대상 모듈의 기존 테스트 코드를 따른다.
3. 수용 조건이 주어졌으면 그것을 케이스 선정의 축으로 삼는다. 구현 코드는 대상 동작을 파악하는 데만 쓰고, 수용 조건과 어긋나는 구현 동작을 기대값으로 삼지 않는다 — 어긋나면 구현 결함 의심으로 보고한다.
4. 요청된 작업(검증·수정·추가·제거)을 수행한다. 대상 모듈의 테스트 소스(`src/test`)만 수정한다.
5. 1과 같은 범위로 테스트를 다시 실행해 전부 통과를 확인한다. 범위 밖 테스트는 실행하지 않는다.

## 출력

- 판정: 통과 / 실패.
- 실행한 명령: 대상 범위를 지정한 gradle 명령 원문(호출 세션이 그대로 재실행해 확인한다).
- 수행 내역: 추가·수정·제거한 테스트 파일과 케이스 수.
- 수용 조건이 주어졌으면: 조건별 커버 여부와, 덮지 못한 조건과 그 이유.
- 실패가 남았으면: 실패 테스트 목록과 원인 추정(구현 결함 의심 여부 포함).

## 종료 조건

대상 범위의 테스트가 전부 통과하고 보고서를 반환하면 완료. 구현 결함으로 통과가 불가능한 테스트는 고치지 않고 실패로 분류해 보고하면 완료.

## 실패 시

구현 코드를 고쳐야만 통과시킬 수 있거나, 대상 범위를 특정할 수 없거나, 빌드 자체가 깨져 있으면 우회하지 않고 시도한 내용과 함께 실패로 보고하고 멈춘다.

## 검증

- 위임 적절성: description만으로 "이 모듈 테스트 보수해줘"(대상)와 "이 버그 원인 찾아줘"(비대상)가 판별되는지 확인한다.
- 출력 계약: 대표 모듈 하나를 위임해 보고서가 출력 형식과 일치하는지 확인한다. 수용 조건을 담아 위임했을 때 조건별 커버 여부가 보고에 나오는지 확인한다.
- 경계: 수행 후 `git status`로 `src/test` 밖 변경이 없는지 확인한다.
- 범위 준수: 클래스 목록으로 위임했을 때 실행 명령에 `--tests` 필터가 붙고 실행 케이스 수가 모듈 전체보다 적은지 확인한다.
